### 5.2 Features

**BLUF:** Three security features guard state changes beyond ordinary trading: capped sandbox self-service, loopback-only admin requests, and an audited kill switch.

**Frame**

- **Who:** Visitors requesting sandbox keys and the owner acting as admin.
- **What:** Sandbox self-service, admin request gating, and the kill switch.
- **Why:** These are the paths where one request can create accounts or stop trading.
- **How:** Address and total caps, header and interface checks, and halts appended to the ledger.
- **When:** On each sandbox or admin request.
- **Where:** `api.py`, `keys.py`, and `adversary_api.py`.

`POST /v1/sandbox/keys` identifies the client by `CF-Connecting-IP` or the
socket peer, creates a $1,000.00 sandbox account at 5 requests/s and returns
its key once, and refuses with 429 after 3 keys per address per 60 minutes,
503 `SANDBOX_CAP` at 300 accounts, and 422 for a label outside
`^[A-Za-z0-9 _-]{1,24}$` (AC-GM-API-06). Any `/v1/admin/*` request carrying
`CF-Connecting-IP` or not arriving on loopback gets 403; on loopback a
missing or wrong admin key gets 401; neither changes state (AC-GM-API-07).
The dashboard's owner controls send a key typed by the owner and never store
it. The kill switch halts the market or one account until the same admin key
lifts it, and both halt and lift are appended to the ledger (AC-GM-ADV-02).
