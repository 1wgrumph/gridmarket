#### Purpose and scope

**BLUF:** This specification exists so judges and implementers can read one coherent architecture for a system built by many parallel agent lanes in under two days.

**Frame**

- **Who:** Judges, the owner, and every lane implementer.
- **What:** The purpose of the document and the extent of the system it covers.
- **Why:** Parallel lanes need a single readable picture of how their parts fit.
- **How:** Sections bind at most five requirements each, and Appendix A traces every bound requirement.
- **When:** Written in phase 1b, revised with each published change.
- **Where:** `spec/GridMarket-Specification.md` on GitHub.

The document covers every component in the design: the market app, its
background tasks, the bot container, the ERCOT Worker changes, the dashboard,
the SDK and examples, the onboarding surfaces, the stretch lanes, and the
spec tooling itself. It states behavior at the level a reviewer needs to check
a merged candidate against the plan.

All submission code is written during the hackathon, from 2026-09-25 17:00
CDT onward, and depends only on open-source releases public for at least 14
days; no code is ported from private repositories (AC-GM-RULE-01). The
repository enforces the commit-time part of this rule with `make rules`.
