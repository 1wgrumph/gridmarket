#### 4.1.12 Specification tooling

**BLUF:** This document is itself built and linted by repository tools, so its structure, traceability, and figures are checked as strictly as code.

**Frame**

- **Who:** Specification authors and the judges who read the result.
- **What:** The spec template, azdiagram, the build and lint tools, and the spec skills (DES-GM-SPEC).
- **Why:** A readable, consistent specification is part of the entry.
- **How:** Markdown sections with BLUF, Frame, and captioned T1–T8 tables and F1–F8 figures; SVG figures from YAML.
- **When:** Rebuilt and linted with `make spec-lint` on every specification change.
- **Where:** `spec/template/`, `spec/gridmarket/`, `tools/`, and `skills/spec-*/`.

azdiagram renders a per-class YAML input to an SVG and a draw.io file from
one Graphviz layout for classes F1–F4, F6, and F7, and from a grid renderer
for F5 and F8; its lint fails on overlapping node boxes or a figure larger
than its declared size (AC-GM-SPEC-01). `tools/spec_lint.py` fails a section
that lacks a BLUF or a Frame field, binds more than 5 requirements, cites a
class outside T1–T8 or F1–F8, or omits a table or figure its content
triggers (AC-GM-SPEC-02). The repository contains the template, the
spec-author, spec-diagram, and spec-lint skills, and this specification,
which passes both lints (AC-GM-SPEC-03). There is no SysML or SysON source
in this lane.
