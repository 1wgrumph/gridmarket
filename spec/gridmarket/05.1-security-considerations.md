### 5.1 Considerations

**BLUF:** The threats that matter are abuse of the public API, replayed or duplicated orders, and credential leakage, and each has a control enforced before any state changes.

**Frame**

- **Who:** Anyone who can reach the tunnel; the owner at publication.
- **What:** Threats to the market, its data edge, and its secrets, with their controls.
- **Why:** A public demo invites automated abuse and secret scraping.
- **How:** Bearer keys stored as SHA-256, Idempotency-Key, token-bucket limits, and a secret scan over full history.
- **When:** On every request, and before the repository is made public.
- **Where:** `api.py`, `.env`, and the repository history.

A request to an account or trading endpoint without a valid key gets 401 and
changes nothing; keys are stored only as SHA-256 hashes (AC-GM-API-01). An
order that reuses an Idempotency-Key replays the original result for an
identical body, returns 409 for a different body, and returns 400 without a
key (AC-GM-API-02). A client over its rate limit gets 429 and changes nothing
(AC-GM-API-03). Before publication the repository has zero secret-scan
findings over its full history and an MIT `LICENSE` (AC-GM-SEC-01).

Table (T6): Threats and controls

| Threat | Asset | Control | Residual risk |
|---|---|---|---|
| Unauthenticated trading | Accounts and ledger | Bearer key, SHA-256 storage | Stolen key until revoked |
| Duplicate or replayed orders | Balances | Idempotency-Key per account | None within stored window |
| Request flooding | Availability, feed | Per-key and per-address token buckets | Buckets reset on restart |
| Sandbox key farming | Market and feed | 3 keys per address per hour, 300 total | Distributed addresses up to the cap |
| Admin takeover from the internet | Bots, outage, kill switch | Admin key plus loopback without `CF-Connecting-IP` | Host compromise |
| ERCOT budget exhaustion | Shared ERCOT limit | Worker allowlist, key, per-client and upstream budgets | Per-location counting of rate-limit bindings |
| Credential leak | ERCOT, Cloudflare, Jev, bot, admin secrets | Untracked `.env`, no logging of keys, secret scan | Owner rotates on leak |
| Prompt injection via other users' text | User agents | MCP returns numbers, ids, and enums only | Text in user-supplied prompts |
