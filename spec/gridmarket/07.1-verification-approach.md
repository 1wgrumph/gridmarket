### Verification approach

**BLUF:** Every slice proves its write set, every assembly step proves the integrated branch still passes, and every phase lands only after one review, at most one repair, and green gates.

**Frame**

- **Who:** Every slice, the Integration Engineer, and the Orchestrator.
- **What:** The verification ladder from slice to landing.
- **Why:** Parallel lanes are safe only if each merge is checked before the next.
- **How:** Test-first lanes; `CMD-WRITESET`; backend tests, dashboard tests and build, and compose smoke after each merge; one phase review and assurance.
- **When:** At each slice exit, assembly merge, and phase landing.
- **Where:** Lane worktrees, `gridmarket/integration-<phase>`, and `main`.

Test Implementer and Product Implementer slices of a lane run in order in one
worktree, and a lane never merges red. Each slice changes only its write set,
and concurrent slices have disjoint write sets (AC-GM-LANE-01). After each
lane merge, the integrated branch passes the backend tests, the dashboard
tests and build, and the compose smoke run before the next merge; a red step
is reverted (AC-GM-LANE-02). A phase that passes assurance merges to `main`
through a PR whose merge commit passes the same gates, and its merged lane
branches and worktrees are then removed (AC-GM-LAND-01).

Table (T3): Verification gates

| Gate | Command | When | Pass rule |
|---|---|---|---|
| Write set | `CMD-WRITESET` | Slice exit | No path outside the slice write set |
| Backend tests | `make test-all` | Slice exit, each assembly merge | Exit 0 |
| Dashboard | `make test-dash` | Each assembly merge | vitest and production build green |
| Smoke | `make smoke` | Each assembly merge | `/v1/market/status` answers from the compose stack |
| Secrets | `make secrets` | Before publication | Zero findings, MIT license |
| Specification | `make spec-lint` | Each spec change | Stable build, zero lint findings |
