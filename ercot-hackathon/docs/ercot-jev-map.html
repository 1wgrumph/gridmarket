ERCOT × Jev Decision Map

Which ERCOT Public API reports can feed calibrated Jev checks, what each check decides, and how the answers get routed. Built from the 116 report products your Worker can reach today.

Read this first: what "trading ERCOT" requires

  • Day-ahead virtual bids, PTP obligations, and offers can only be submitted by a registered Qualified Scheduling Entity (QSE), through EWS or the MIS portal.
  • CRRs (congestion rights) require registration as a CRR Account Holder, with credit posted to ERCOT.
  • Without registration, the common routes are exchange-listed ERCOT futures and options through a futures broker, partnering with an existing QSE, or controlling a physical asset such as a battery.
  • The Public API is read-only and mostly delayed or disclosure data. It supports signals, research and paper trading, not order entry. This page is a technical map, not investment advice.

How data flows into decisions

Everything below the Worker line runs on Cloudflare. Jev answers each check with a calibrated probability, and the router turns that probability into an action.

Phased build

In build order. Each phase depends on the one before it.

  1. Foundation deployed

    ercot-hackathon Worker, B2C token cached in KV, generic report proxy, NP3-907-EX demand-curve page with GSAP.

  2. Ingest the real-time core

    Cron Triggers and a Queue pull hub/zone SPPs, SCED lambda, system demand, price adders, wind and solar actual vs forecast. Raw JSON to R2, tidy rows to D1, latest values to KV.

  3. Feature store and labels

    D1 views for DART spread, forecast errors, reserve proxy and constraint recurrence. Backfill history for the same reports so every feature has matching outcomes.

  4. Jev checks

    Define each check as a typed schema (inputs, horizon, threshold, outcome rule) and call jev-gateway for calibrated probabilities. Start with the DART check because labels arrive daily.

  5. Router, ledger and scoring

    Confidence bands, the abstain rule, Slack alerts, a paper-trade ledger in D1, and Brier score and reliability tracking per check.

  6. Decision dashboard

    Live signals, the review queue and calibration charts on the Worker's GSAP front end.

  7. Execution path decision

    Choose between partnering with a QSE, a futures broker account, or a storage partner. Any real order stays behind human approval.

  8. Reuse

    Expose the checks as MCP tools so Organized Router and other agents can ask the same calibrated questions.
