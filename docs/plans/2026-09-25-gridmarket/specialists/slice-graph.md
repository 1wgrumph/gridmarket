Supporting file, not a canonical artifact. `implementation.json` (Plan

roles, write sets, and dependencies below are fixed by Planning and Design;
command IDs are proposed and finalized by the Planning Test Engineer in

## Build strategy (DEC-GM-038, DEC-GM-039, DEC-GM-040)

- **Package landing first (CF-21).** Before S01 dispatch, the Orchestrator
  commits the approved planning package on `gridmarket/lifecycle-setup`,
  pushes it, and lands it on `main` through a PR with a merge commit; lane
  `foundation` and `gridmarket/integration-1a` branch from that `main` commit.
- **Contract-first.** Wave 1 is S01, the skeleton that freezes every shared
  name (modules and files, Python types, API routes, request and response
  fields, headers, ledger and event entry types, bot profile schema, check
  and router schema, MCP tool names and arguments, the Worker snapshot
  contract, dashboard page routes and data hooks) as code stubs plus
  `CONTRACTS.md` (AC-GM-CONTRACT-01), together with the owner's Worker
  security fix S24-S25. A later name change is a contract amendment recorded
  in `CONTRACTS.md` on branch `gridmarket/contract-<n>` (CONTRACT-GM-INDEX)
  and merged into every lane that uses the name.
- **One wide parallel wave.** Wave 2 holds every feature lane of phases 1a,
  1b, 2 and stretch. Each lane starts as soon as its dependencies allow, in
  its own worktree, and is limited only by disjoint write sets and route
  capacity. Lanes whose tests need another lane's behavior code against the
  stubs and, before their exit, merge `main` after the named phase landing
  (stated in the slice goal).
- **Wave 3 (final, short):** user guide, `llms.txt`, onboarding skill, README
  Contributors section (S44-S45), and quick website onboarding (S47-S48),
  assembled by S46 before the Sun 07:00 CDT freeze.
- **Declared phases and assurance (DEC-GM-038):** phases 1a, 1b, 2, stretch,
  and final. Each phase: Integration Engineer execution (its assembly slice),
  then one Reviewer pass and one Test Engineer assurance pass on the
  integrated phase candidate, at most one repair round, deterministic
  verification of the repair (CMD-TEST-ALL, CMD-SMOKE, CMD-SECRETS,
  CMD-RULES), no re-review. The final wave is not named in DEC-GM-038;
  Planning applies the same rule to it (proposal, owner may drop the review).
- **Landing hygiene (DEC-GM-040):** after a phase passes, the Orchestrator
  pushes `gridmarket/integration-<phase>`, opens the PR to `main`, merges it
  with a merge commit, then deletes every lane branch (local and remote) and
  worktree whose slices are all merged, and the phase integration branch and
  worktree. A lane is deleted only when the phase evidence marks every slice
  merged and not reverted, the remote lane tip equals the recorded exit SHA,
  and `git diff --quiet <exit> origin/main -- <lane write-set union>` passes;
  otherwise it is kept and listed for the owner (CF-27). `main` stays demoable after every merge.
- **Route load split (DEC-GM-040):** at most 2 concurrent sessions on a
  usage-windowed primary route (AGY, 5-hour window; Muse or Codex if limits
  appear); further concurrent sessions go to the ordered fallbacks,
  proactively. Planning proposal for other routes: at most 3 concurrent
  sessions per harness route. On verified exhaustion all new sessions move
  down the fallback order. Every placement is recorded in a route receipt.
  Reasoning levels are the frozen snapshot values (DEC-GM-042; DEC-GM-041
  revoked): Muse routes run at max.
- **Priority** when route capacity is short: phase 1a lanes, then 1b, then
  2, then stretch; within a phase, lanes on the critical path first
  (foundation, worker, market, data, ui, bots, router, pages, views, spec).

Development strategy: `tdd` (frozen profile); the spec lane (S19-S21) is
`single_implementer` on the tech-writing profile; the UI lanes `ui`,
